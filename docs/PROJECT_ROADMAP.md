# ClashToSingBox 项目路线图

本文档是项目后续工作的总览入口，用于记录当前基线、阶段目标、任务边界和详细任务文档。具体施工步骤与验收标准应放在对应任务文档中，避免在总览中重复维护实现细节。

## 当前基线

截至 2026-08-01，项目已经具备以下能力：

- 支持 VMess、Shadowsocks、Trojan、VLESS 和 AnyTLS。
- Validator 已拆分为共享能力、协议私有校验器和主路由。
- Converter 采用稀疏输出，不生成空对象或无意义默认字段。
- 已提供标准 PowerShell 模块清单 `ClashToSingBox.psd1`。
- 已有 Pester 单元测试和完整输入到输出的集成测试。
- 源码已经公开上传到 GitHub。

以上内容描述的是当前能力，不代表后续阶段已经完成。

## 路线图

### R1：GitHub CI 质量门禁

目标：让 Pull Request 和 `main` 分支上的代码自动完成跨平台测试、静态检查、模块清单验证与实际导入验证。

状态：待实施。

详细任务：[CI/CD 流水线任务拆分](./CICD_TASKS.md)

### R2：GitHub Release 自动打包

目标：以版本标签为唯一正式发布入口，验证标签与模块版本一致，并生成内容干净、可直接安装的 Release 压缩包。

状态：待实施。

详细任务：[CI/CD 流水线任务拆分](./CICD_TASKS.md)

### R3：PowerShell Gallery 发布

目标：在 GitHub Release 稳定后，引入人工批准和受保护密钥，将正式版本发布到 PowerShell Gallery。

状态：候选阶段，尚未决定是否实施。

详细任务：[CI/CD 流水线任务拆分](./CICD_TASKS.md)

### R4：协议与共享能力扩展

目标：根据实际需求增加协议或字段，同时保持共享能力和协议私有字段的分层边界。

当前候选项：

- 决定是否实现 WebSocket `max_early_data`。
- 决定是否实现 WebSocket `early_data_header_name`。
- 若不实施，则删除代码中的预留注释并在文档中明确不支持。

状态：待决策。

### R5：仓库与文档维护

目标：保持 README、目录说明、测试基线和发布状态与实际代码一致。

持续检查项：

- README 的支持协议、质量状态和发布方式是否准确。
- `docs/PROJECT_STRUCTURE.md` 是否符合实际目录。
- `myinputs/`、`outputs/` 和本地生成内容是否保持在版本控制边界之外。
- 已完成的临时分支和过期文档是否及时清理。

状态：持续维护。

## 实施顺序

建议按以下顺序推进：

1. 完成 R1，让所有后续改动先受到自动质量门禁保护。
2. 完成 R2，建立可重复、可验证的 GitHub Release 流程。
3. 根据实际分发需求决定是否完成 R3。
4. 在 CI 稳定后继续 R4 的功能扩展。
5. R5 贯穿所有阶段，每次功能或发布变更同步维护文档。

## 路线图维护规则

- 阶段开始前，应在对应任务文档中确认边界与验收标准。
- 任务只在代码、自动化配置和验证证据均完成后标记为完成。
- “工作流文件已创建”不等于流水线已验收；至少需要 GitHub 上的真实运行结果。
- 被明确推迟的工作应标记为候选或待决策，不应写成已经支持。
- 新增长期任务时，先在本路线图登记，再链接到独立任务文档。
